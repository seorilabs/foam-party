# UI 실행 화면 검수

`game-ui-design` 스킬의 실행 검수 기록이다. 시안 승인 절차 없이, 현재 실행 화면을
그대로 보고 수정 대상을 구체화한다.

## 재현

캡처는 결정론적 스크립트로 언제든 다시 만든다. PNG는 저장소에 넣지 않는다.

```bash
FOAM_SHOT_DIR=<출력 경로> godot --path godot \
  --script res://tests/screenshot_scene.gd --audio-driver Dummy
```

- viewport `390x844` (design size와 동일), safe area inset 없음
- 저장 파일 82장. 화면·상태·툴·레벨·텍스트 배율·언어를 포함한다
- 실기기가 아니라 **viewport 테스트**다. 기기 검증을 대신하지 않는다

캡처 타이밍은 연출 길이를 반영해야 한다. 별은 완료 후 `STAR_REVEAL_DELAYS`
(0.3/0.75/1.25초)에 순차 등장하므로, 그보다 짧게 기다리면 별이 모두 비어 있는
프레임이 찍혀 실제보다 나쁜 검수 결과가 나온다.

## 2026-09-22 검수

revision `105ab0b` 기준, Godot 4.7.2, 에셋은 `godot/assets/art/asset-manifest.json`
12종 중 툴 아이콘·코인·별만 통합된 상태.

### 판정

| 항목 | 판정 | 근거 |
| --- | --- | --- |
| 구도·시선 | 통과 | 각 화면에서 플레이 대상과 주 행동이 먼저 읽힌다 |
| 형태·재질 | 수정 필요 | 같은 때(dirt)인데 잎은 텍스처, 흙·먼지는 절차적 점이라 재질이 섞인다 |
| 배경·글자 | 통과 | 타이틀 부제 겹침을 해소했다. 100%·150%, 한글·영문에서 잘림이 없다 |
| 정보 위계 | 수정 필요 | 게임플레이 일일 미션이 번호와 진행 바만 있어 어떤 미션인지 알 수 없다 |
| 상태 | 통과 | 업그레이드 아이콘 실루엣을 확보했다. 잠금·토글은 색 외 신호를 함께 쓴다 |
| 피드백 | 미검증 | 정지 캡처로는 입력-결과 연결을 확인할 수 없다. 녹화 검수 필요 |

### 수정한 결함

| # | 화면·상태 | 증상 | 원인 | 수정 |
| --- | --- | --- | --- | --- |
| 1 | 타이틀 (100%·150%) | 부제 `TITLE_SUBTITLE`이 상단 아이콘·글자 배율 칩에 가려 일부만 보였다 | 부제 baseline `y=128`, 폰트 16 → 약 `y=116~132`. 상단 버튼 행은 `TOP_BUTTON_Y=104` + 높이 30 → `y=104~134`로 같은 밴드. 부제는 폭 390 전체 중앙 정렬이라 버튼 x영역을 피하지 않았다 | 부제를 `_title_subtitle_baseline()`(버튼 행 아래 16px)으로 내리고, hero 패널 상단을 그 아래에서 시작시켰다. 하단 경계 372는 유지해 미션 카드·시작 버튼 레이아웃은 그대로다 |
| 2 | 완료 패널 | 뒤의 코인 칩·진행 토스트·별 트래커·미션 패널·툴바가 그대로 읽혀 모달과 경쟁했다. 코인 칩과 "거의 다 됐어요!" 토스트가 같은 자리에서 겹쳤다 | 디밍 알파가 `0.35`라 밝은 HUD 카드를 덮지 못했다 | `_completion_overlay_active()`를 두고 완료 중에는 플레이 HUD를 아예 그리지 않는다. 배경과 차만 알파 `0.45`로 가라앉힌다 |
| 3 | 업그레이드 상점 | 첫 항목 `바람 강화`의 아이콘이 보이지 않았다 | 아이콘 누락이 아니라 `_upgrade_tool_color(TOOL_AIR)`가 `#d8eef5`로, 패널 배경 `#f7fbff` 위에서 경계가 사라진 것이다. soap `#f8f4a6`도 같은 위험이 있었다 | 타이틀 스킨 스와치와 같은 네이비 `#123246` 아웃라인을 둘러 실루엣을 확보했다 |
| 4 | 캡처 스크립트 | 완료 캡처에서 별 3개가 모두 회색으로 찍혔다 | 게임 결함이 아니라 `_settle(12)`(약 0.2초)가 `STAR_REVEAL_DELAYS` 최댓값 1.25초보다 짧았다 | 완료 캡처 전 대기를 90프레임으로 늘렸다. 재캡처에서 `earned_stars=2`가 정확히 노란 별 2개로 나온다 |

### 소명 — 의도된 설계이거나 초기 진단 오류

| 관찰 | 판단 |
| --- | --- |
| 완료 화면의 `광고 보고 코인 2배` 버튼이 회색이다 | 의도된 fail-closed다. `active = not claimed and ads != null and ads.is_rewarded_ready(...)`이고, 캡처 환경에는 광고 SDK가 없다. 실기기에서 인벤토리가 준비되면 초록 + 재생 삼각형으로 바뀐다. 미준비 중에도 행을 유지해 레이아웃이 튀지 않게 한 것도 의도다 |
| 일시정지에서 `Reduced Motion Off`만 회색이다 | 토글 표현은 일관적이다. 켜짐 `#d7f8e5`, 꺼짐 `#e5eef5`가 모든 토글에 같이 적용되고, 라벨이 On/Off를 함께 말하므로 색 단독 신호가 아니다. 캡처 시점에 이 항목만 꺼져 있었을 뿐이다 |
| 150%에서 툴 힌트가 부스터 칩과 붙는다 | 겹치지 않는다. 힌트는 고정 폭 `Rect2(22, y, 244, 30)`이고 폰트만 `_fit_fs`로 줄어, 부스터 칩까지 약 10px 여유가 남는다. 여유가 빠듯하므로 부스터 칩 폭이 늘어나면 다시 확인한다 |
| 완료 시 하단 툴바가 활성으로 보인다 | 수정 #2로 함께 해소됐다 |

### 남은 개선 — 시각 방향 결정 필요

에이전트가 임의로 정하지 않는다. 방향을 고른 뒤 같은 기준으로 구현한다.

| 항목 | 현재 | 문제 |
| --- | --- | --- |
| 게임플레이 일일 미션 | 번호(1·2·3)와 진행 바만 그린다. 라벨은 타이틀 카드에만 있다 | 플레이 중에는 어떤 미션인지 알 수 없다. 플레이를 방해하지 않으려 압축한 의도는 타당하나, 현재 형태로는 진행 바의 의미가 전달되지 않는다 |
| 버튼 색 체계 | 타이틀 보조 4개가 파랑·보라·회색·주황, 일시정지가 7색이다 | 주 행동(초록)과 위험 행동(빨강)은 규칙이 있으나, 보조 행동이 카테고리별 색으로 갈려 동등하게 강하다. 시선이 분산된다 |
| 때(dirt) 재질 | 잎은 텍스처, 흙·먼지·기름은 절차적 도형이다 | `dirt_mud`·`dirt_grime`·`foam_cluster`·`bubble`이 생성만 되고 통합되지 않아 한 화면에서 재질이 섞인다 |

### 미검증

- 입력·보상 피드백, 연속 탭, 드래그-클릭 오작동 (정지 캡처의 한계, 녹화 필요)
- 실기기 화면·safe area (viewport 테스트만 수행)
- 작은 화면·긴 화면 (390x844 단일 viewport만 확인)
